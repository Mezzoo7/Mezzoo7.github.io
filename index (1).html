Reconnaissance and attack-surface assessment

Authorized target: certifiedhacker.com · Illinois Tech coursework · [Month Year]

Scope
Passive and active reconnaissance of a single public domain and its mail, DNS, and hosting infrastructure. No exploitation.
Method
WHOIS and DNS enumeration (dig, nslookup), subdomain discovery with theHarvester and Netcraft, path analysis with traceroute, service and version detection with Nmap, web checks with Nikto, then manual validation of each candidate CVE.
Outcome
Eight-page report covering executive summary, passive findings, active findings, vulnerability analysis, and prioritized remediation. Twenty-one subdomains mapped, including exposed administrative interfaces.
  • HighMySQL 5.7.44 and PostgreSQL reachable from the public internet — no network-level restriction on database ports.
  • HighNo DMARC record and a neutral SPF policy (?all), leaving the domain trivially spoofable in phishing campaigns.
  • MediumCleartext FTP (Pure-FTPd) exposed on port 21 alongside credentialed webmail and cPanel interfaces.
  • Ruled outA reported Exim vulnerability (CVE-2010-4344) flagged by version matching was manually tested and confirmed not exploitable — reported as a false positive rather than padding the finding count.

Applied cryptography lab

GPG, OpenSSL, hashing and encoding on Kali · ITMS 448 Cyber Security Technologies · September 2026

Scope
Four exercises: symmetric encryption with GPG, asymmetric RSA with OpenSSL, cryptographic hashing, and base64 encoding.
Method
Generated an RSA keypair and encrypted and decrypted with rsautl, compared MD5, SHA-1 and SHA-256 digest lengths, produced a salted SHA-256 hash with mkpasswd, and verified that base64 is encoding rather than encryption.
Outcome
Found two errors in the lab instructions. The handout's file-integrity command hashed the file path string rather than the file's contents, which would make it useless for detecting tampering. The handout also expected CAST5 as the default GPG cipher, written for GPG 2.0, while the current release defaults to AES-256. Noted that rsautl is deprecated in OpenSSL 3.0 in favor of pkeyutl.
